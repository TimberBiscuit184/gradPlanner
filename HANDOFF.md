# Sprout — handoff

Written 2026-08-18 for a fresh session on a different machine. Everything below
was measured on that date, not remembered — re-run the commands and trust those
numbers over this file if they disagree.

---

## 1. The goal

**A degree planner every BYU-Idaho student can open, pick their major, and lay
out their whole degree in — not just the next semester.**

It reads the university's published catalogue: 2,031 courses, 353 programs,
which semesters each class actually runs in, what it needs first and what it
unlocks. The student drags courses onto a board of semesters; the app checks
prerequisites, term availability, credit load and same-semester blocks, and
**warns rather than refuses**, because a half-built plan is a normal thing to
have.

It is going to the university for students to use. That sets the bar: it has to
be right, it has to say how confident it is, and it must never quietly invent a
requirement.

**Next milestone: sign-in, so a student's plan follows them between the desktop
app, a laptop and the web.** Today the plan lives only on one machine. See §8.

## 3. Running it on a new machine

```bash
git clone https://github.com/TimberBiscuit184/gradPlanner.git
cd gradPlanner
npm install
npm run dev          # browser, localhost:5175
npm run desktop      # Electron shell
npm run build && npm run desktop:build   # packaged installer
```

Two things a clone will not have:

- **`data/student.mine.json`** — the owner's real transcript, gitignored on
  purpose. `npm run verify` reads it for ~20 assertions about a real record. It
  is not needed to run or build the app; the shipped `data/student.json` is
  deliberately blank so a new user starts clean. Without it those assertions
  fail or skip.
- **`scripts/.shotplans.json`** — generated by `npm run shots:plans`.

Windows note: Bitdefender has quarantined freshly-built `.exe` files here
before. `npm run shortcut` runs the untouched Electron binary instead, which
sidesteps it.

## 5. How the data actually works

This is not a CRUD app. The catalogue is harvested, parsed, graded for
confidence, and only then trusted. The chain:

```
harvest:programs  ->  data/programs-raw.json   (verbatim HTML, never parsed on the way in)
merge:programs    ->  data/programs-generated.json  (Bucket trees + a trust grade)
audit:programs        did the parse lose anything? six checks
sweep                 open every degree cold — does the app work?
verify:catalog        is the harvest still what the live catalogue says?
```

Two trust models gate what the app is willing to assert:

- **`PrereqTrust`** — `human | exact | parsed | unsure | none`. `enforcesPrereq`
  lets `exact` hard-block, because it was measured: 86 of 86 correct against
  hand-audited courses.
- **`ProgramTrust`** — `assertsRequirements` is true for `human`, `exact` and
  `parsed`. **`unsure` never asserts**, because that grade is assigned when the
  build *knows* the reading is incomplete.

The governing principle throughout: **never refuse from an unverified reading.**
A false refusal ("you can't take this") is worse than a false permission,
because the student can check a permission and cannot recover a class they
didn't register for.

## 7. What changed this session

**Catalogue coverage finished.** Specializations harvested (132 across 22
programs), clusters and certificates generated, and the last prose-stated
requirements resolved — department lists, subject codes, level filters,
shorthand course lists ("MUSIC 312, 313, 314"), number-suffix rules. Audit went
from 187/209 clean to **353/353**, and `unsure` from 21 to **0**.

**Enforcement turned on.** `exact` and `parsed` programs now assert
requirements; `unsure` still does not. This exposed a bug the old policy had
been hiding: `requiredCourseIds()` walked *every* asserting program and cached
globally, which marked **941 courses across the whole university as ★ required
for every student**. It is now per-enrolment and follows `programRef`.

**Same-semester constraints** read out of the catalogue (`Bucket.sameTerm`),
warning when a block is split. Also `allowDoubleCount` from "No double
counting".

**Planner credit cap fixed** — a check-then-act gap: it read the term's load,
then resolved corequisites (which can place courses into that same term), then
added its own course without looking again. Nursing got a 19-credit semester
under a 16-credit cap.

**Restyled to Sprout** from the website: Public Sans / Bricolage Grotesque /
JetBrains Mono, warm-paper light theme as default, dark kept and toggleable.
All colour lives in `src/index.css`; there are **zero hardcoded hex values in
`src/`**. Renamed everywhere a user can see — but **`gradtree:*` storage keys
and `window.gradtree` deliberately unchanged**, because renaming a storage key
orphans every plan already saved on a student's machine.

**Tree layout rebuilt.** 1,033 prerequisite edges were drawn level with or right
of the course that needed them — backwards arrows. Columns are now a longest
path over the edges actually drawn, chosen per cluster against the old global
depth on evidence (fewer backwards edges, then fewer crossings). Corequisite
pairs sit adjacent. **Backwards edges 1,033 → 0; crossings down 67%.**

**First-run walkthrough** — six skippable steps with major/minor selection
inline.

**21 showcase screenshots** in `screenshots/`, generated from real planner
output.

**Git history scrubbed.** The repo contained the owner's transcript with grades
in `data/student.json`, a duplicate root `student.json`, and — missed on the
first pass — inside `files.zip`. All purged from both commits and force-pushed.
`scripts/scanSecrets.py` now checks history *including inside archives*.

## 8. What did not work, and why

Kept because each one cost real time and would cost it again.

**Writing code through shell heredocs.** This bit four separate times. `\b` in a
heredoc becomes a literal backspace byte (0x08), so `/\b[A-Z]{2,7}\b/` becomes a
regex that silently never matches; `\n` inside a JS string literal becomes a
real newline and a syntax error. The tell is a regex that is obviously correct,
tests correct in isolation, and returns nothing in place — `cat -A` shows it as
`^H`. **Use the editor, not heredocs.**

**Auditing a re-derivation instead of the artifact.** `auditPrograms.ts`
re-ran the parser and measured *that*, so it never saw what `buildPrograms.ts`
adds afterwards, and reported 34 already-fixed buckets as broken. Audit the
thing you ship.

**Checks that were wrong in the pessimistic direction.** Sorting term ids as
strings puts `2027F` before `2027S` before `2027W` — Fall, Spring, Winter,
backwards — which reported 216 prerequisite violations in a correctly-ordered
plan. Separately, validating a placement against a board that already contained
it flagged 4,659 of 4,669 as duplicates. A harness that is wrong pessimistically
costs more than no harness, because you go hunting a bug that does not exist.

**Top-level-only tree walks.** Three separate checks looked only at top-level
buckets and missed nested ones: the hollow-requirement check, the `programRef`
counter (which invented a shortfall and downgraded 13 programs), and the
unsatisfiable check. When a check walks a tree, walk the whole tree.

**Assuming instead of reading the catalogue.** "Complete 1 of the following"
with *named* options ("Economics Minor", "Animal Reproduction Cluster") was read
as a checklist because the parser only recognised blocks headed "Option N".
Agribusiness became a 272-credit demand for a 120-credit degree.

**A modal broke every driver.** Adding the first-run walkthrough silently
invalidated the setup step of `ui:check`, `tree:check` and `shots`, which all
clear localStorage and expect a blank app. They now set
`gradtree:onboarded:v1`.

**`git filter-branch` deleted untracked files.** It checks out the rewritten
tree, which removed `data/student.mine.json`; `git gc --prune=now` then
destroyed the old objects. The transcript was recovered from a zip in the
commit still on the remote — but that was an older snapshot, and the official
`_transcript` GPA figures were lost for good. **Copy anything precious out of
the repo before history surgery.** The seven GPA assertions now skip, loudly,
until those four numbers are pasted back from I-Plan:

```
SKIP  GPA vs official transcript — data/student.mine.json has no
      _transcript block. Paste the cumulative quality points, GPA
      credits, attempted credits and GPA from I-Plan to restore it.
```

They were deliberately **not** reconstructed from the app's own maths — that
check exists to test the app against independent figures, and computing them
from the app would make it pass by construction while testing nothing.

## 9. Next steps

### Phase 1 — sign-in and sync (the milestone)

**Goal:** a student's plan follows them between the desktop app, another
computer, and the web.

**Design constraint that should not be negotiated away: stay offline-first.**
The app works today with no network at all, and that is a feature for a student
on campus wifi. Local storage stays the source of truth; sync is additive.
Concretely:

1. **The plan is a small JSON document** (~5 KB: placements, enrolled program
   ids, preferences). It is not relational data. Store it as a document keyed
   by user, not as a row per placement.
2. **Anonymous local use must keep working.** Sign-in is opt-in; a student who
   never signs in loses nothing.
3. **Sync on a whole-document basis with a version number and a
   last-write-wins prompt.** Two devices editing one plan is a real conflict;
   asking the student which one to keep is honest and cheap. Do not attempt
   CRDTs for a 5 KB document.
4. **Auth: use a provider, do not build it.** Supabase Auth, Clerk or Auth0.
   The university may want SSO against BYU-Idaho accounts eventually — pick a
   provider that supports SAML/OIDC so that is a configuration change later,
   not a rewrite.
5. **Desktop uses the system browser for the OAuth leg**, not an embedded
   webview, with a loopback redirect. Tokens go in the OS keychain via
   `safeStorage`, **not** `localStorage` (see §10).

Rough shape:

```
POST /auth/*            handled by the provider
GET  /api/plan          -> { version, updatedAt, document }
PUT  /api/plan          <- { version, document }   409 on version mismatch
DELETE /api/account     -> deletes everything, immediately
```

That is four endpoints. Resist more.

### Phase 2 — scaling and hosting

- **The web build is a static site.** 2.3 MB of JS today; that is the thing to
  fix (below), not the hosting. Netlify/Vercel/Cloudflare Pages, no server.
- **Split the bundle.** `index-*.js` is **2.34 MB** because
  `courses-full.json` (1.29 MB) and `programs-generated.json` (896 KB) are
  imported directly and inlined. Serve them as fetched, cached, gzipped assets
  instead, and load the program a student actually picked rather than all 353.
  Expect roughly a 10× reduction in first paint cost.
- **Precompress.** Those JSON files gzip to a fraction of their size and are
  fully static. Serving them uncompressed is the single biggest quality miss
  today.
- **Cache with the catalogue year in the URL** (`/data/2026-2027/courses.json`)
  so a new catalogue is a new URL and nothing goes stale.
- The desktop app should keep bundling the data — it must work offline.

### Phase 3 — clean code

- **`Tree.tsx` is ~900 lines** and does layout, rendering, viewport control and
  interaction. Split: layout is already extracted (`treeLayout.ts`); pull the
  node component and the viewport controller out next.
- **`Header.tsx` holds four unrelated components** (search, programs, plan
  actions, focus). Split by responsibility.
- **Module-level mutable singletons** — `ACTIVE` in `scope.ts` and the caches
  keyed off it — are a genuine bottleneck and the reason a stale memo left the
  tree empty. They work because the app is single-user and single-window. If a
  server ever evaluates two students at once, they break. Pass a context
  object instead.
- **Update dependencies**: 1 high-severity dev vulnerability, and React types,
  dagre and `@vitejs/plugin-react` are majors behind.
- Add a **LICENSE** — there is none, which is a problem for handing anything to
  a university.

## 10. Pre-ship audit

**Today: no server, no database, no accounts, no uploads, no API keys, no
telemetry, no third parties, nothing leaves the device.** Most of this list is
therefore "not applicable *yet*". Every one of them becomes live the moment
Phase 1 ships — treat this as the gate for that release, not a list of current
sins.

### Quality

| Check | Today | Before ship |
|---|---|---|
| Uncompressed JSON | **Live problem.** 2.34 MB single JS bundle, data inlined | Split + fetch + gzip/brotli; version by catalogue year |
| One-at-a-time database writes | n/a — no database | Plan is one document; write it as one document. Never a row per placement |
| Single-dependency bottlenecks | **Partly live.** Module-level `ACTIVE` + caches in `scope.ts`; whole app depends on one bundled data blob | Pass context instead of module state before any server evaluates two users |
| Un-optimistic rendering | n/a — everything is local and synchronous | On sync, render the local change immediately and reconcile after; never spinner-block a drag |
| Non-statically-hosted site | n/a — no web deployment yet | Static host. The app needs no server of its own beyond the four API routes |

### Legal

| Check | Today | Before ship |
|---|---|---|
| Privacy policy | **None exists** | Required before any student uses it, even with no accounts |
| Discloses AI/automated processing | Not stated in-product | **Say it plainly.** Requirements are machine-read from the catalogue; the `auto-read` badge implies it but a policy must state it |
| "We collect user data" | True today: **nothing is collected** | After sign-in: email + plan document. Say exactly that, and nothing vaguer |
| Third-party data collectors | **None** — no analytics, no fonts from CDNs, no trackers | If any are added, name them individually |
| Delete user uploads / data | n/a — no uploads | `DELETE /api/account` must actually delete, immediately, not soft-delete |
| Storage bucket public | n/a — no bucket | If one is ever added: private by default, signed URLs only |
| Fake testimonials | Website has no testimonial markup (2 uses of the word "review", neither a claim) | Keep it that way. No invented students, no invented numbers |
| Licence | **No LICENSE file** | Add one before handing it to the university |
| Accuracy disclaimer | In-app: "confirm with an advisor" in the walkthrough and requirements panel | Keep it. It is the most important sentence in the product |

### Security

| Check | Today | Before ship |
|---|---|---|
| `.env` in git | **None**, tracked or on disk | Keep it out; `.gitignore` it before the first key exists |
| API keys in the front end | **None** | Anon/publishable keys only; anything secret stays server-side |
| Row-level security | n/a | **Mandatory.** A student reads and writes only their own plan row. Enforce in the database, not the client |
| Front-end permissions | n/a | Never the authority. The client may hide a button; the server decides |
| Rate limiting | n/a | On auth and `PUT /api/plan` at minimum |
| SQL string concatenation | n/a — no SQL | Parameterised queries or an ORM, always |
| Server-side input validation | n/a | Validate the plan document against a schema on write. Reject unknown fields |
| Rendering user content as raw HTML | **Clean** — no `dangerouslySetInnerHTML` in `src/` | Keep it. Course text is catalogue data, but treat it as untrusted anyway |
| Passwords in plain text | n/a — no passwords | Use the provider. Never store or hash your own |
| Admin panel without auth | n/a — no admin panel | If one appears, authenticate it on day one |
| Auth tokens in `localStorage` | n/a — only plan/profile/theme there | **Desktop: OS keychain via Electron `safeStorage`. Web: httpOnly, Secure, SameSite cookies.** Not `localStorage` |
| CORS `*` | n/a | Lock to the known origins, including the Electron origin |
| Email verification | n/a | Require it before a plan syncs |
| Predictable IDs without ownership check | **Partly relevant.** Plan ids are local and meaningless today | Server must check ownership on every read and write, regardless of id shape |
| Saving a whole request body on update | n/a | Accept only the plan document, validated. Never spread a request body into a record |
| Webhooks without signature check | n/a — none | Verify signatures if any are added |
| Production stack traces | Electron shows dev tooling only in dev | Generic error to the client; detail to the log |
| Dependency updates | **0 production vulnerabilities, 1 high in dev deps**; several majors behind | `npm audit fix`, then plan the React 19 / dagre 3 upgrades |
| Password strength / breach check | n/a | Provider handles it — turn it on |
| File uploads without validation | n/a — no uploads. **Import plan…** reads a local JSON file | Validate the imported document against a schema, cap its size, never `eval` it |

### Also worth doing

- **The transcript import path is the sharpest edge.** If students ever paste or
  upload an I-Plan transcript, that is sensitive academic data and changes the
  privacy analysis completely. Design it to stay on-device if at all possible.
- **Keep `scripts/scanSecrets.py` in CI.** It exists because a text-only scan
  missed a transcript inside a zip and pushed it.
- **Re-run `npm run verify:catalog` each catalogue year.** It compares the
  harvest to the live catalogue and is the only check that notices BYU-Idaho
  changing a requirement.
